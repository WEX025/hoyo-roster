Use the current AI client's built-in browser on every OS; Codex uses its in-app browser. Bootstrap and select it through the host's documented browser tools, then retain the actual browser object. Never pass only its ID, launch a separate browser, export cookies or read authentication databases.

## Start the connected task

The installed Python package must match the selected source. Do not substitute a stale installed package. Missing client connection gives CLIENT_BROWSER_REQUIRED. Each game checks its own required sources before identity reads or business writes; a failed game's capability check does not skip the next game.

For repeatable timed Genshin+ZZZ sync, use the repository entrypoint described in [timed collection](../../../docs/timed-collection.md): import tools/timed_collection.mjs, call startTimedCollection(browser, options) ONCE, and retain the returned session. It performs a live clean-source/installed-byte preflight before browser access, writes private per-step logs and owns process/settings cleanup. Pass the selected absolute Python, a NEW log directory outside the checkout, the SAME shared runtimeRoot across runs, and explicit parallelGames. Each active call awaits session.advance(); the next call resumes the same session. Never start a replacement task just because a foreground slice ended. For login answers use session.host.answerLogin with the attempt rules below; user cancellation calls await session.cancel().

For sync/discover, import src/hoyo_roster/client_runtime.mjs and call createRosterHost(browser). It assembles game-owned DOM readers and the existing API readers; do not use an unconfigured low-level host or ask the executing agent to implement readSource. The default page path does not require CDP. It reads official UI identity, owned rows and current details twice, validates and atomically saves a partial page snapshot. Read [page observations](../../../docs/page-observations.md) for format and field boundaries. If the selected client lacks DOM access, games separately check the API path's advertised capabilities. Never invent API responses, HTTP status, numeric IDs or completeness evidence from DOM observations.

For standalone login, import src/hoyo_roster/client_host.mjs and createClientHost(browser); login has no data-reader dependency. Use host.startTask with the selected Python 3.12 environment, repository cwd and requested game/operation; default sync handles Genshin then ZZZ. storageRoot and runtimeRoot are optional documented overrides. The host starts a private worker pipe; do not run --client-stdio in a visible terminal.

## Login module

Timed sessions perform pumping internally: only await session.advance(), and use session.host for login answers. The task/host instructions below describe ordinary low-level callers; import client_runner.mjs and explicitly await pumpWindow(task) or pumpSlice(task) inside each active client tool call. Its ten-second launch window plus a forty-five-second in-flight source needs at most fifty-five seconds. With startTask({parallelGames:true,...}), one task overlaps at most two different game sources; each game remains serial and actual source starts share a two-second gate. The window drains browser work before returning, immediately hands back login questions, and never performs background browser work. Pipe callbacks only queue requests. Each bundled source step has a 45-second deadline, including preparation; cancellation prevents later browser actions. For each new host.pendingQuestion().attempt, proactively ask whether the person finished login in the official page, using the available user-input tool. Retain that attempt value with the question; suppress repeated prompts for the same waiting attempt. Choices: 已完成登录 / 尚未完成 / 取消. The user handles phone, OTP, QR confirmation, agreements, image verification and submission in the page; do not solicit or enter credentials, send SMS or check agreements.

Keep host/task bindings and the same browser/page alive while waiting. Call host.answerLogin("completed", question.attempt) only after explicit confirmation for that attempt. If the person already said “已登录” for this attempt, use that answer without asking again. A new login attempt after explicit expiry requires a fresh confirmation; never reuse an earlier attempt's answer. Use host.answerLogin("waiting", question.attempt) for an explicit not-yet response and wait for the person; do not repeatedly re-prompt. Use host.answerLogin("cancel", question.attempt) or task.cancel() on cancellation. Elapsed time is never a confirmation.

The login module returns at user confirmation, with the same session/page; no identity probes, roster reads or business writes occur inside it. It does not close the shared browser.

## Continue the game task

Keep pumping until done; each game owns identity checks, both passes, normalization, validation and saving. The page path reads the official role selector, never substitutes user confirmation for identity, and currently requires a unique bound role. API-mode ZZZ alone owns service initialization/refresh. Both paths reuse the same session and restart only the current uncommitted game once on auth recovery; completed games stay saved. Login confirmation is not the end of a collection task.

Inspect task.status() for fixed progress, questions and errors. Use game=all; parallelGames=false retains sequential Genshin then ZZZ for comparison, while true overlaps games in one session/lease. On concurrent authentication expiry, quiesce in-flight sources, recover once, reverify pinned identities and serially restart uncommitted games; keep completed results. Immediately continue the next active window when no question is pending; defer aggregate analysis until completion. Drain host.drainMetrics() into private timing records, separately from PAGE_TIMING/CLIENT_TIMING, without summing nested or overlapping spans. task.completion settles after process closure; check its exit code and protocol result. Do not await completion alone while requests need pumping. At every task end, await completion, then await host.releasePageSettings() in an active tool call; cancel first on tool failure or user cancellation. Normal pump completion also restores temporary zero-viewport repairs. Retain the shared browser and pages. Source callbacks stop on AbortSignal; source failure is not successful collection.

Keep consecutive windows in the SAME active foreground tool invocation when the client supports it, instead of returning to the model after every ten-second window. Bound the foreground slice to the client's verified outer deadline, leaving room to drain a full in-flight source and return. The tested desktop's outer MCP deadline is 300 seconds even with a larger requested timeout: use a 180-second launch slice and a 270-second execution timeout there, then immediately resume the same task in the next active call. This is foreground work, not a detached/background loop. Each window still drains before returning; login questions end the slice immediately. Other clients need their own verified budget.

The packaged `pumpSlice(task, options)` implements the bounded foreground loop; the timed session uses it automatically. Do not rewrite this loop or invent a timing callback. Ordinary untimed callers may use `pumpWindow` or `pumpSlice` directly and retain responsibility for cleanup.

After timed completion, run `python tools/analyze_collection.py --run RUN_DIRECTORY --compare BASELINE_DIRECTORY --output REPORT_DIRECTORY` (omit `--compare` for a single run). It validates committed two-game page results, double-roster/identity evidence and saved snapshots, calculates source union/overlap and window gaps, and compares normalized private data. A speed comparison with different data or source is explicitly flagged. Report this as offline replay, never as a fresh live collection. Do not commit private run logs or snapshots. See [timed collection](../../../docs/timed-collection.md) for exact files, invocation and validation boundaries.

Report page saves as OFFICIAL_PAGE / PARTIAL, with actual counts and paths. They do not meet API complete coverage and never overwrite API generations. HSR is paused; Genshin excludes artifacts/full stat panels. For offline API-generation maintenance read [local use](../../../docs/local-use.md). Do not explore old private directories or generalize session retention to client restarts or untested platforms.
