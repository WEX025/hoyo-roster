# 数据格式和完整度

默认页面采集使用独立的 `hoyo-roster-page-v1` 格式，固定为 `partial`，位于 `page-observations-v1`；其字段、身份、两轮检查及原子保存规则见[页面记录](page-observations.md)。以下 Profile/roster/builds、数字 ID、完整度及代际说明适用于原有 API 快照，不能要求 DOM 读取器伪造这些 API 字段，也不能用页面结果覆盖它们。

**崩坏：星穹铁道暂时无法获取，请不要使用。原神目前不含圣遗物和完整属性面板。** 以下区分当前可用能力与保留的技术格式；星铁接口/格式继续存在，不是使用建议，也不推断上游原因。

格式权威是发行包的 `src/hoyo_roster/contracts/schemas/`；验证器同时验证 schema、跨文件一致性、完整度、规范 JSON 和 roster/build 一一对应。`data/manifest.json` 列出三游戏文件。每个身份的当前 generation 只包含本游戏数据、本游戏 schema 和必要公共契约。运行时只验证本游戏；公共 manifest 保留固定格式映射，但不要求其他游戏文件存在。整仓三游戏空基线验证保留为开发发布检查。结果使用 game-results-v3 新命名空间，generation/transaction 归属标记升级为 v3，旧目录不自动读取或迁移。

Profile 保存游戏、UID、server、nickname、player_level 和 sync（state/source/synced_at）。名单的字符串角色 ID 是 map key；Build 为 `builds/<正整数角色ID>.json`，不重复存储角色身份。百分比为比例值（例如 5% → 0.05），精确数字通过 Decimal 与规范序列化保留；三游戏数据均不经 float 回读。规范 JSON 为两空格缩进、末尾换行，数字使用普通十进制、去除无意义的小数末尾零，负零写为 0；拒绝非有限值。独立验证器精确回读再比较规范文本，星铁的高精度 Decimal 同样适用于离线验证和恢复。只保存各游戏当前已支持的装备字段（原神当前武器等，不含圣遗物），不保存库存、货币、资源、目标配装、推荐结果或公共游戏机制数据库。

| 游戏 | 正式状态 | 来源和完成条件 | 缺失行为 |
|---|---|---|---|
| 原神 | `partial`（字段覆盖有限） | 本人官方 Binding + 计算器页面自然请求的单页完整角色列表；精确 UID/区服/请求字段，total 和 size 证明闭合 | 目前不含圣遗物和完整属性面板；名单仍须闭合，部分/未知多页契约拒绝，不能冒称 complete |
| 绝区零 | `complete` | 官方 Binding、战绩角色名单与养成 owned 名单严格相等；逐角色详情与批量详情恰好覆盖名单，邦布名单闭合；两次完整度证据相同 | 未知分页、重复/遗漏 ID、来源不一致、缺少必需属性失败；schema 明确允许的可选值可为 null |
| 崩坏：星穹铁道 | **暂时无法获取，请不要使用** | `hsr` 实现与既有 `partial` 格式仅保留供开发和既有数据解释 | 不推荐用户运行登录或采集；历史合成测试通过不证明当前可用 |

原神保留来源支持的等级、突破、命座、好感、技能和当前武器等有限字段；目前不含圣遗物和完整属性面板，`partial` 不表示接受残缺角色名单。绝区零包括代理人等级、晋阶、影画、技能、音擎、驱动盘、面板和邦布；`complete` 指已实现来源和 schema 的闭合，不表示游戏账号所有信息。

两次采集比较业务数据和来源覆盖，发现漂移就停止；生命周期拒绝不允许的身份变化、名单缩小、进度回退或字段覆盖回退。禁止增加逐字段 coverage 数据；来源诊断只在内存中用于验证。

星铁保留格式仅供开发和既有数据解释（当前不可用，请不要使用）：旧实现描述的角色等级、技能、光锥、遗器与面板子集不构成当前能力承诺。其 materialize/lifecycle 仍解释历史数据的旧值保留，Profile 时间戳不能说明全体角色均刷新；未证明 owned roster 时保留旧角色值，空基线保持空名单。这些规则不授权用户运行星铁采集。

`not_synced` 是未收集基线，不能把空名单当作已收集的空账号。`synced_at` 是本次保存业务快照的 UTC 时间，无变化时保持此前值。正式数据通过 candidate 验证和完整安装验证后才成为 current。
