# 内置浏览器页面采集

createRosterHost(browser) 优先装配两游戏的页面读取器，复用同一个活浏览器和登录问答模块。没有 DOM 接口时才检查原有 API 读取路径；缺少 CDP 本身不再使页面采集失败。Python 不启动浏览器，不复制认证材料。

## 字段与来源

| 游戏 | 页面读取内容 | 处理规则 |
|---|---|---|
| 原神 | 官方角色切换面板身份、已拥有名单及等级、同步后的三项技能名称/显示等级、当前武器名称/等级 | 通过计算器选择角色，每批四名；页面须显示“已同步拥有角色的信息”。等级对的左侧为当前值，右侧计算目标不保存 |
| 绝区零 | 官方角色切换面板身份、已拥有名单及等级、当前音擎/技能/驱动盘区块的文字 | 名单中的 Lv. 标记作为拥有证据，`-` 预览排除。按姓名选择代理人，等待目标标题及当前区块稳定；只保存“当前”区块，不采入推荐方案 |

两游戏分别拥有页面选择器与字段映射，公共 client_page.mjs 仅处理浏览器引用、只读 DOM、稳定加载、取消及来源封装。页面角色面板必须只有一个可核验身份；多个绑定角色当前明确停止，不任意选择。区服保存官方显示名称，不伪装成 Binding 返回的区服代码。身份在采集前后及两轮之间重新核验；明确失效才调用共享登录流程。

页面来源沿用私有 source.read 管道，来源名为 page:identity、page:roster、page:detail。json 是所读 DOM 字段的结构化记录；origin 只包含 kind=official-page、game、确切官方页面 URL，evidence 为 surface 与 generation。API 路径仍核验原始响应及 HTTP 来源，两种来源不能互相冒充。页面输入读取仅限计算器已显示的业务数值；不读取任何登录输入值、Cookie、隐藏应用状态或浏览器数据库。

## 保存格式

页面结果固定为 format=hoyo-roster-page-v1、state=partial、scope=rendered-owned-characters。profile 包含官方面板 UID、昵称和区服显示名称；roster 是姓名及等级数组，details 与其逐一对应。姓名是当前语言页面的匹配标签，不是官方数字实体 ID。

原神详情使用 name、level、skills（category/name/displayed_level）和 weapon（name/level）。官方同步页明确显示“点击添加”且没有武器等级输入时，weapon 保存 null，表示页面未提供当前武器；其他武器字段缺失仍失败。绝区零详情使用 name（已点击的名单标签）、display_name（实际详情标题）、current_weapon、current_skills、current_discs，保留当前区块原文与精确数字文本；名单简称与详情全名分别记录。读取器核对选择器关闭以及标题/当前区块完成切换，不能把上一名角色数据关联到下一名。技能显示顺序不擅自映射成接口 ID，显示等级不擅自扣减影画加成。未读到的数字 ID、属性、原神突破/命座/好感及绝区零完整驱动盘副词条和邦布不补默认值。

绝区零音擎详情区明确标记 EMPTY 时，current_weapon 保存 null；必须来自“音擎”详情容器的空态标记，不能把推荐区的 EMPTY 或缺失标题当作空装备。没有驱动盘时保留官方“尚未装备驱动盘”区块原文。

当前原神官方计算器明确提示“奇偶”相关计算暂不支持；只有实际点击该角色并观察到此官方提示时，才在 details 中保留 name/status=unsupported/reason，名单和等级仍保留。普通点击失败、加载超时或缺详情不能套用该记录。两轮的此状态和原因同样必须一致，报告 PAGE_DETAILS_UNAVAILABLE；已有可读详情不能静默回退成 unsupported。

范围仅为页面已呈现的拥有名单及其对应详情，不声称服务端分页完整或满足原 API complete 契约。两轮必须同身份、同名单、同详情；重复姓名、遗漏详情、跨轮漂移均失败。原神还须核对详情当前等级与名单等级相等。

结果位于结果根的 page-observations-v1，按游戏/UID 派生哈希隔离。每个身份的 snapshot.json 在结果锁内完整校验，再通过现有私有文件、文件刷新、原子替换及父目录刷新工具更新。已有记录先校验身份、格式、名单不缩小及角色等级不回退；业务数据不变则不重写。替换前失败保留旧文件，替换后持久化未知则报告错误并保留现存文件，不清理可能有效的结果。

页面存储不修改 API 的 game-results-v3、候选、current 指针或代际恢复逻辑。正常报告包含 SNAPSHOT_KIND=OFFICIAL_PAGE、COLLECTION_STATUS=PARTIAL、PAGE_CHARACTER_COUNT 和 CURRENT_RESULT。只有两轮、校验、保存及会话锁释放后才能报告任务 PASS；PASS 不改变 partial 字段范围。

## 执行与收尾

使用现成 createRosterHost 和 host.startTask，在每个主动客户端工具回合 await pumpWindow(task)。每个来源总期限为45秒；页面动作后检查状态，等待稳定后读取，取消后不继续采集。浏览器仍与官方页面通信，个人数据只经私有管道保存本机。

绝区零已识别的“方案更新提示”只通过“知道了”关闭，再继续读取当前数据；不选择“切换方案”或同步更新。角色选择或身份面板的点击只有在观察到目标状态未变化时才做一次有限修复；未知弹窗、登录和验证流程不由此代处理。

游戏读取器在首次读取、更换页面或登录 generation 变化时刷新当前标签，清除中断遗留界面及另一标签登录后的过期 SPA；每轮名单读取仍单独刷新。在同一活页与 generation 内，身份复核重新打开官方角色面板并读取 UID/区服/昵称，不缓存或沿用旧身份值，也不额外整页刷新。名单卡片只有在选择面板实际可见时使用，不能以隐藏 DOM 的存在代替面板打开；角色切换判定与是否装备音擎无关。

“方案更新提示”可能在操作之后异步出现，也可能处于标题尚在、按钮已消失的关闭动画中。打开面板的等待过程继续处理这个已识别提示，确认其完全关闭；状态未变化时至多再点一次目标，不连续重复点击。官方明确显示“出错了，请重试”时，只通过同页“重试”恢复一次，重新核验身份后重做该来源；未知错误、认证错误或再次失败照常上报，受同一来源总期限约束。

历史保留页成为零尺寸、无法点击时，读取器可在同一个客户端浏览器中新建该游戏标签页并重新核验身份；保留原页，不复制凭据或另启浏览器。若新页仍为零尺寸，仅通过公开 viewport 能力临时恢复布局；正常视口保持原样。正常 pump 收尾恢复临时设置；异常或取消时先等待 task.completion，再主动 await host.releasePageSettings()。共享浏览器与登录态保留。

完整 API 模式及旧输出字段条件见[数据格式](data-format.md)；实际验收范围见[验证状态](release-validation.md)。

## 页面采集性能与计时

原神每轮名单读取准备一次页面和官方身份，详情批次在同一页通过正常历史返回重新打开选择器，按观察到的选中集合做差量选择，不再每批整页刷新。轮次上下文仅限本轮活页面、身份及登录 generation；新的名单读取重新准备，身份来源读取或来源失败清空上下文。批次仍为四名，两轮仍分别重新读取全部详情；原神批次还检查当前昵称，轮次前后仍核验官方 UID 与区服。

绝区零每轮完整读取名单；详情只打开选择器并验证目标已拥有卡片，不重复扫描全部名单。页面更换或 generation 变化拒绝旧上下文。已知弹窗、官方一次重试和当前区块稳定判定保留。

Python 的 PAGE_TIMING 只记录固定游戏/操作、请求序号及耗时，区分 gate、source_roundtrip、validate、save、game。gate 单独记录计划/实际等待及元数据保存耗时；两秒最小间隔保持不变。createRosterHost 返回 drainMetrics()，提供脱敏来源和页面阶段耗时；调用方定期取走，不能将父子跨度直接相加。

主动工具回合调用 client_runner.mjs 的 pumpWindow(task)，启动窗口最多十秒，来源期限至多四十五秒，工具预留最多五十五秒。串行逐条推进；显式 parallelGames:true 时可同时处理两条不同游戏来源，每游戏内部串行，实际来源启动仍共享两秒间隔。返回前收拢全部在途浏览器动作；遇到登录问题立即交还，不在后台控制浏览器。最终完成仍等待进程退出、锁释放和 releasePageSettings。

绝区零通过官方拥有卡片上可见的 `.gt-card__content.active` 判断当前代理人：重复选择已激活卡片允许标题不变，但仍要求选择面板关闭、当前区块完整且连续两次读取一致。选择新角色仍要求标题变化或观察到加载过渡，不能把旧角色详情关联给新目标。面板未关闭时只在观察确认后修复一次。常规打开面板和卡片点击改用明确状态检查，省去未使用的全页快照；原神普通标签点击缩短为200毫秒，仍保留最终精确选中集合与一次有界修复。
