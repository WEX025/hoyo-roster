# 当前验证状态

实现按[四模块工作流](workflow.md)执行：client_host.mjs 保持客户端活浏览器，私有管道连接 Python，登录模块只等待用户确认，游戏模块自行检查身份、采集两轮、校验和保存。依赖和源码不再包含独立浏览器登录驱动。

## 当前已验证范围

- 当前 Codex 内置浏览器真实页面：用户登录原神后刷新及关闭标签重开仍保持；绝区零官方角色面板无需再次登录即可显示本人绑定角色。这个结果仅证明网页会话复用。
- 合成来源回归：生产 ClientSession、登录模块、原神与绝区零游戏流水线、规范化、候选和存储运行真实代码；覆盖同会话、单次登录、第二游戏失效、采集中失效、账号变化、取消、缺失来源能力、错序/换会话及保存。
- Node 宿主使用真实 Python 子进程和私有管道，通过合成来源完成“用户确认→两游戏两轮→验证→保存”；不是只模拟 Python 函数返回。
- donor 移植回归将合成边界下移到 CDP 事件：实际执行内置读源器的请求构造、签名、请求体证明、响应读取、服务初始化、生产宿主、Python worker 与双次验证保存；不再仅用一个返回 fixture 的 readSource 回调。另测服务回执不传认证字段、不得访问 Cookie 值、重登失效缓存、来源超时与迟到动作停止。
- 交接故障回归包含启动失败后重试、挂起 SDK/来源取消与迟到结果、等待确认时关页、旧 attempt 回答拒绝，以及登录打开/确认/身份复查失败后停止后续游戏。协议回归也检查无完整帧的 EOF、超限未结束帧和不响应正常终止的工作进程。
- 存储和平台回归继续检查真实临时文件、锁、保存恢复、精确 Decimal；Windows mock 不作为实机证据。交付报告另给固定源码与工作区指纹、实际命令及统计。

## 当前真实数据阻塞

根因是迁移时删除了已有真实采集实现，却没有交付新后端的等价实现；不能表述为项目从来没有实现采集。[PR #9](https://github.com/WEX025/hoyo-roster/pull/9) 记录了 `e0d06b8` 在 Windows Chromium 上完成两游戏真实账号采集与保存；这属于当时版本的历史验收记录，不能替代当前版本的实测。PR #10/#11 仍保留真实采集代码。

明确回归发生在 [PR #12](https://github.com/WEX025/hoyo-roster/pull/12) 的开发提交 [f0f9c8a](https://github.com/WEX025/hoyo-roster/commit/f0f9c8aec8e72f61262c9c480af27ca354c3f3cc)，合并后为 `6a5f040`。较早的四模块/共享会话重构 `48420d6` 和清理提交 `be46f16` 仍保留下面的采集通道；破坏点是最后的浏览器后端替换。

| 旧版本真实实现 | PR #12 的变化及影响 |
|---|---|
| 原神 `games/genshin/browser.py`：`OfficialCollector.binding` 通过同一 BrowserContext 读取 Binding，`cultivation_list` 监听官方 request/response，读取角色 ID、技能和武器的完整响应 | 删除该文件，改为 `source.read` 请求，但新宿主只有默认 `readSource = null` 的注入点，未提供实际读源代码 |
| 绝区零 `games/zzz/browser.py` 与 `transport.py`：在同一会话观察所需设备头，通过 BrowserContext 请求注册接口，执行 DS、节流及响应校验 | 删除页面准备和设备头观察，`BrowserTransport` 被替换为同样依赖空读源点的 `ClientTransport`；运行依赖中的 Playwright 也被删除 |
| 绝区零 `endpoints.py` 的 `_cultivate_login` 与 `BADGE_LOGIN`：建立/刷新游戏养成服务自己的会话 | 调用与端点一并删除，新适配器没有承接该职责；共享账号登录本身不能证明每个游戏服务的会话初始化已完成 |
| 原有 `test_game_chains.py`、`test_account_workflow.py` 等采集/共享会话测试，以及真实账号验收 | 相关测试被删除并新增合成 reader 管道测试；新测试直接返回 fixture 数据，只能验证读源之后的处理，无法证明真实 reader 存在 |

因此这是可定位的采集功能回归，修复对象应包含真实传输、游戏服务初始化及它们与共享会话的衔接。旧实现使用的是完整 Playwright BrowserContext；新要求使用的是 AI 客户端内置浏览器。不能把旧实现直接接到只有 DOM 操作的对象，也不能在没有等价适配和真实验收时删除旧实现或宣称迁移完成。

此前只有游戏隔离与诊断的修改尚未恢复核心读源；当前工作区进一步以 d2b70ac 为 donor 开发 client_network.mjs、两个游戏的 client_source.mjs 和装配入口 client_runtime.mjs。正式 createRosterHost 自动注入实际读源器，保留客户端内置浏览器登录，未恢复独立 Profile/登录自动化。绝区零恢复了养成服务初始化，并以 service.prepare 的认证内容隔离回执替代 Cookie 检查/清理；服务内局部刷新与账号重登分开处理。公共网络层和宿主不导入游戏实现，只有装配入口选择游戏插件。

2026-10-15 对当前 Codex 内置浏览器再次实测：浏览器能力为 visibility、viewport；官方原神计算器和绝区零养成指南标签页能力为 pageAssets、webmcp，两页面均返回无 WebMCP 工具。未发现受支持的完整业务响应读取接口。这是当次客户端/页面的观察，不能硬编码为以后运行的能力判定。

原神“已拥有”列表可读取 96 个角色的姓名和等级；角色编辑页显示同步提示、技能名称与等级、当前武器名称与等级，但列表和已检查详情未暴露所需的官方数字角色 ID。不能据此生成当前契约要求的完整名单和 Build 文件。绝区零养成指南复用登录、可显示绑定角色，但公开代理人列表包含明确标为“未拥有”的预览方案，不能当作本人角色或装备；战绩移动页在桌面端跳转至推广页，修改 viewport 没有改变结果。没有将观察数据冒充正式角色快照。

移植适配器基于本机浏览器运行时的公开 CdpTabCapability.send/readEvents 文档实现，只在标签页声明该能力时调用。当前 Codex 标签页未声明 CDP，故生产入口有实现但能力检查返回缺项；没有尝试访问未开放能力，也没有将登录改到独立浏览器。DS/接口常量来自 donor，当前官方接口及跨平台真实可用性仍待在线验收，不能把代码存在等同于当前客户端能执行。
