# 四模块工作流

业务模块为登录、原神、崩铁、绝区零。各游戏拥有身份核验、采集、标准化、校验和保存；崩铁采集暂停。桥接、锁、节流和存储为公共工具。

## 登录和交接

所有操作系统使用当前 AI 客户端的内置浏览器；Codex 使用 Codex 内置浏览器。用户在官方页面自行处理手机号、验证码、扫码、协议和图片验证。

登录模块打开官方登录页并主动询问是否完成。用户确认后立即结束，返回同一活会话和页面引用；尚未完成则等待，取消则停止。用户已针对本次尝试主动说“已登录”时不重复询问；认证再次失效则开启新尝试，重新取得确认。登录模块不做 Binding、UID 或区服核验，不抓角色、不写结果，也不关闭共享浏览器。

客户端宿主 client_host.mjs 保持实际浏览器对象。Python ClientSession 经私有双向管道调用宿主，所有调用关联同一会话和递增请求 ID。login.open 打开或复用官方页面，login.confirm 挂起直到本人答复，返回 LoginHandoff；source.read 仍由同一宿主在同一浏览器处理。序列化标识只关联管道请求，不被当成另一进程的浏览器连接。

## 游戏和保存

默认按原神→绝区零。每个游戏先在自己的 source/entry 中读取官方身份；有效则继续，明确认证失效才调用登录。用户确认后，当前游戏继续核验官方 game/UID/region，不把确认当成身份验证。

身份在任务内固定。重新登录后，SessionService 调用各游戏已注册的身份核验回调；账号变化停止。游戏间正常共享登录，绝区零单独失效时只恢复绝区零；采集中失效最多重登并重做当前游戏两轮一次，不重抓原神。

恢复边界包含用户登录完成后的固定身份复查与当前游戏的首次身份核验；任一步失败都停止账号任务，保留具体固定错误代码。全部核验通过后才发布恢复后的会话版本。普通游戏读源失败则按游戏失败汇总，两者不因错误代码相同而混淆。

各游戏采集两次并比较业务和来源覆盖，使用现有规范化、Decimal、lifecycle、schema、名单/Build 闭合检查后自行保存。普通单游戏来源或保存失败允许后续游戏继续；身份、风控、限流、认证恢复或管道失败停止账号任务。最终成功须等结果事务完成、锁释放，共享浏览器保留。

## 能力不足与终止

宿主没有活内置浏览器：CLIENT_BROWSER_REQUIRED。宿主未接入受支持的数据来源：CLIENT_SOURCE_UNAVAILABLE，在登录或创建业务结果前停止。等待确认时页面关闭：下一次主动 pump 返回 CLIENT_PAGE_UNAVAILABLE。错序/换会话/EOF/无效 JSON：CLIENT_PROTOCOL_ERROR。本人取消：LOGIN_CANCELLED；取消中止宿主等待、终止并回收工作进程，进程关闭后释放浏览器占用，保留浏览器。每种情况都有接收方和终止结果，不会把用户确认悬置成“已完成采集”。

readSource 是客户端数据源适配点，必须使用宿主受支持的接口返回已注册来源的原始 JSON 文本与覆盖证据。没有该能力时不能凭空实现，更不能以独立网络请求、认证导出或绕过导航限制替代。

宿主先校验启动参数再取得浏览器占用；启动失败释放占用并报告固定错误。启动后以工作进程关闭为任务收尾边界，取消不依赖未完成的浏览器或来源调用。适配器收到 AbortSignal 后须停止后续浏览器动作；宿主丢弃迟到结果。正常结束、取消、管道损坏都由同一收尾路径释放占用，后续任务可继续借用该浏览器。

当前 Codex 已验证网页层面的原神登录保持及绝区零绑定角色复用；当前官方页面没有可用 WebMCP 数据工具，现有浏览器接口未暴露所需完整响应读取。因此当前 Codex 默认宿主的真实完整采集返回 CLIENT_SOURCE_UNAVAILABLE。管道、登录交接、双游戏规范化和保存可以用合成来源整链验证；它不代表真实来源采集已通过。
