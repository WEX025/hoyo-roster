# 四模块工作流

业务模块为登录、原神、崩铁、绝区零。各游戏拥有身份核验、采集、标准化、校验和保存；崩铁采集暂停。桥接、锁、节流和存储为公共工具。

## 登录和交接

所有操作系统使用当前 AI 客户端的内置浏览器；Codex 使用 Codex 内置浏览器。用户在官方页面自行处理手机号、验证码、扫码、协议和图片验证。

登录模块打开官方登录页并主动询问是否完成。用户确认后立即结束，返回同一活会话和页面引用；尚未完成则等待，取消则停止。用户已针对本次尝试主动说“已登录”时不重复询问；认证再次失效则开启新尝试，重新取得确认。登录模块不做 Binding、UID 或区服核验，不抓角色、不写结果，也不关闭共享浏览器。

正式采集入口 client_runtime.mjs 的 createRosterHost(browser) 装配两个游戏的读源插件与低层 client_host.mjs；宿主持有实际浏览器对象。Python ClientSession 经私有管道调用，全部关联同一会话与递增请求 ID。login.open 打开或复用官方页面，login.confirm 等待本人答复后返回 LoginHandoff；source.read、service.prepare 由同一宿主在同一浏览器处理。序列化标识不被当成另一进程的浏览器连接。

## 游戏和保存

默认并行采集原神与绝区零。每个游戏先在自己的 source/entry 中读取官方身份；有效则继续，明确认证失效才调用登录。用户确认后，当前游戏继续核验官方 game/UID/region，不把确认当成身份验证。

默认在一个总任务和会话锁下交叠两游戏，各游戏内部保持串行。请求按递增 ID 发出，允许不同游戏的响应乱序完成并按 ID 路由；最多两条在途，拒绝同游戏重叠。来源共用两秒节流，宿主还约束实际启动间隔，防止工具调用间隙积压后突发。显式 `parallelGames: false`（worker 参数 `--no-parallel-games`）保留串行用于对照和兼容。

并发期间认证失效会先停止未提交游戏轮次并收拢已发请求，再统一进入既有登录及固定身份复查，之后串行重做未提交游戏；已经保存游戏保留。再次失效不会复用先前确认。身份冲突、风控、限流和管道错误中止整个账号任务。

身份在任务内固定。重新登录后，SessionService 调用各游戏已注册的身份核验回调；账号变化停止。游戏间正常共享登录，绝区零单独失效时只恢复绝区零；采集中失效最多重登并重做当前游戏两轮一次，不重抓原神。

恢复边界包含用户登录完成后的固定身份复查与当前游戏的首次身份核验；任一步失败都停止账号任务，保留具体固定错误代码。全部核验通过后才发布恢复后的会话版本。普通游戏读源失败则按游戏失败汇总，两者不因错误代码相同而混淆。

各游戏优先使用官方页面 DOM：角色切换面板身份、已拥有名单和全部对应详情采集两次，比较并校验后保存 partial 页面记录。页面来源、字段和保存契约见[页面记录](page-observations.md)。DOM 不可用时可检查保留的 API 来源，其 Decimal、schema、lifecycle、名单/Build 和服务端闭合要求保持不变。普通单游戏来源或保存失败允许后续游戏继续；身份、风控、限流、认证恢复或管道失败停止账号任务。最终成功须等结果事务完成、锁释放，共享浏览器保留。

API 路径的绝区零养成服务通过同一浏览器初始化，失效先在游戏内刷新一次再进入账号恢复。初始化、DS 和设备头均归游戏，响应体不进入管道，只返回 ready/origin。新登录确认递增 generation，游戏自行废弃缓存。页面路径由官方 UI 加载自己的服务，采集器不另发初始化请求。

## 能力不足与终止

宿主没有活内置浏览器：CLIENT_BROWSER_REQUIRED。宿主未配置真实读源适配器：SOURCE_ADAPTER_MISSING；适配器已接入但当前游戏所需来源不支持：CLIENT_SOURCE_UNAVAILABLE。能力检查由各游戏拥有，列出 MISSING_SOURCE 并在该游戏身份读取和业务写入前失败，后续游戏继续；不存在全局读源预检。等待确认时页面关闭：下一次主动 pump 返回 CLIENT_PAGE_UNAVAILABLE。错序/换会话/EOF/无效 JSON：CLIENT_PROTOCOL_ERROR。本人取消：LOGIN_CANCELLED；取消中止宿主等待、终止并回收工作进程，进程关闭后释放浏览器占用，保留浏览器。

readSource 使用宿主受支持接口返回已注册来源记录。API 来源保持原始 JSON 与 HTTP 证据；页面来源明确为 official-page 和实际 DOM 字段，不虚构 HTTP 响应、数字 ID 或服务端分页。缺失能力不能由独立网络、认证导出或绕过导航限制替代。

宿主先校验启动参数再取得浏览器占用；启动失败释放占用并报告固定错误。启动后以工作进程关闭为任务收尾边界，取消不依赖未完成的浏览器或来源调用。适配器收到 AbortSignal 后须停止后续浏览器动作；宿主丢弃迟到结果。正常结束、取消、管道损坏都由同一收尾路径释放占用，后续任务可继续借用该浏览器。

生产入口装配了游戏 DOM 读取器与保留的 API 读取器；页面路径不要求 CDP。API 路径仅访问已声明的 CDP，不寻找调试地址、启动其他浏览器或导出认证。每个来源含页面准备总计45秒。主动窗口最多十秒启动预算，返回前收拢在途浏览器动作；并发最多两条不同游戏请求，不在管道后台操作浏览器。零尺寸视口的临时布局设置在收尾恢复；异常或取消时等待进程结束后主动调用 host.releasePageSettings()。实际页面采集和完整 API 验收分开记录，见[验证状态](release-validation.md)。

## 运行入口

AI 使用 [local-roster skill](../.agents/skills/local-roster/SKILL.md) 调用[持久化工作流](timed-collection.md)的统一入口，按 nextAction 推进；完整页面同步不临时拼装命令。底层宿主、独立登录和桥接协议见[客户端桥接](client-bridge.md)。Python CLI 不再自行启动浏览器。离线检查与恢复见[本机使用](local-use.md)，数据范围见[数据格式](data-format.md)，验收范围见[验证状态](release-validation.md)。
