# 当前四模块工作流

业务模块为账号登录、原神、崩铁、绝区零。默认命令按原神→绝区零顺序运行。崩铁的公开 discover/login/sync 入口返回 `GAME_PAUSED`，既有格式、开发实现和离线维护继续保留，不代表当前可采集。

每个游戏先通过 `AuthService` 核验同一账号会话；缺失或过期才调用登录，成功后继续当前游戏。账号模块拥有唯一持久 Profile/Context，各游戏借用独立页面。账号锁覆盖实际上下文生命周期；认证不依赖角色结果目录，不读取原神/绝区零业务 Profile 来决定登录身份。省略 UID 时由游戏适配器从官方 Binding 发现本人身份；显式 UID 仍须官方 game/UID/region 证明。

原神、绝区零分别负责采集、标准化、校验和保存，通过注入的公共工具完成候选及原子提交。结果配置仅含结果范围和游戏身份，不含认证根。每次运行只读取本游戏数据和契约；整仓三游戏验证仅用于开发发布。共享 JSON、锁、节流和存储工具不另算业务模块。`workflow.py` 只选择游戏、顺序调用、汇总结果；`discovery.py` 只使用游戏提供的身份接口，不调用 CLI 或检查采集器内部属性。

采集中认证过期时废弃未提交的两轮采集，最多重新登录并重做当前游戏一次，不重抓已完成游戏。普通单游戏服务、来源、schema 或保存错误继续后续游戏并汇总失败；身份冲突、风控、限流和共享认证恢复失败停止账号任务。最终 PASS 在浏览器关闭且锁释放后输出，已保存结果独立报告提交状态。

需登录时先取得方式与官方通信/专用会话允许；已给出的授权不重复询问。辅助手机号流程在一次发码获严格回执后主动询问验证码，隐藏输入代填并提交一次；已识别协议仅按单独授权代勾。二维码确认、图片 CAPTCHA 及未知新协议/权限仍由本人处理。普通控件延迟出现时自动有界等待。一次发码授权不自动续用；真实副作用结果不确定时停止自动重试。

当前认证只使用 `<认证根>/account-session-v1/`，结果使用 `<结果根>/game-results-v3/`。旧目录不搜索、不读取、不迁移、不删除。旧 `--resume-discovery` 只保留明确拒绝入口，所有操作均在接触私人路径前返回 `DISCOVERY_RESUME_UNSUPPORTED`；没有恢复、搬移或继续旧短信授权的兼容分支。

平台浏览器选择由 `browser_runtime.py` 集中处理，首次选择后固定，认证失败不切换浏览器。当前使用细节见[本机指南](local-use.md)，数据边界见[数据格式](data-format.md)，隐私见[隐私说明](privacy.md)。固定旧版本的实现和验证已移入 [history](history/README.md)，不能取代当前说明或最新真实账号验收。
